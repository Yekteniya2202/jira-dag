# Jira DAG

Редактор направленного графа задач Jira для Windows, Linux и браузера. Карточки показывают статусы и Story Points. Стрелки представляют связи Jira, а пунктир обозначает иерархию задач.

## Использование

1. Подключи **Jira Cloud** через URL сайта, email и API-токен. Для токена с заданными разрешениями включи **scoped**. Для **Jira Data Center** укажи базовый URL, включая контекстный путь при наличии, и Personal Access Token. Имя пользователя в форме необязательно.
2. Введи JQL, например `project = APP ORDER BY key ASC`, или ключ задачи. Выбери глубину от 0 до 3, чтобы догрузить связи за пределами выборки. Узлы вне выборки отмечены пунктирной рамкой.
3. Выбери карточку, чтобы подсветить связанные ветки и увидеть открытые блокеры. При нескольких полях оценки выбери нужное поле слева и нажми **Загрузить граф**.
4. Нажми **Новая задача** или **Следующий шаг**, чтобы создать задачу в Jira. Протяни стрелку между карточками, чтобы создать связь выбранного типа. Типы, включая пользовательские, приложение читает из Jira. Для `blocks` редактор проверяет циклы в загруженной части графа.

Для чтения нужны права просмотра выбранных задач. Для записи нужны права на создание или редактирование задач и управление связями. Автор новой задачи берётся из текущего профиля Jira. Кнопка **+** на карточке открывает создание следующей задачи с выбором типа связи. При частичном сбое после создания можно повторить привязку по её ключу. Кнопка **Открыть описание** показывает Markdown в модальном окне. Форматированное описание Jira Cloud редактируется в Jira.

Граф зависит от JQL, глубины и прав текущей учётки. При достижении лимита или невозможности догрузить соседние задачи интерфейс показывает предупреждение. В режиме **Без групп** карточки можно перетаскивать. Позиции сохраняются при обновлении того же запроса и сбрасываются при смене запроса или раскладки.

### Выборка и раскладка

Выбери проект Jira и уточни условия выборки перед загрузкой графа. Статусы, типы задач, релизы и спринты доступны в списках после выбора проекта. В разделе **Команда проекта** есть поиск и аватарки пользователей, которым Jira разрешает назначать задачи. Доступность списка зависит от разрешений и ограничений Jira. Метки и другие значения можно ввести вручную. Все условия собираются в один редактируемый JQL. Нажми **Загрузить граф**, чтобы применить его. Если черновик отличается от применённого запроса, под редактором виден JQL загруженного графа. Числа рядом со значениями относятся к задачам текущей загруженной выборки. Глубина **Только выборка** показывает задачи, найденные по JQL. Для добавления соседних задач выбери глубину от одного до трёх переходов.

Открой **Сохранённые фильтры**, чтобы дать текущей выборке имя и использовать её на любой вкладке. Открой новую вкладку кнопкой **+**. Вкладки можно перетаскивать или перемещать через **Shift + ←/→**. Кнопка с булавкой закрепляет активную вкладку слева. Порядок и закрепление сохраняются. У каждой вкладки свой черновик JQL, применённый запрос, фильтры, раскладка и настройки отображения. В свёрнутой панели **Подсветка задач** можно выделить задачи по тексту и полям. В меню **Видимость связей** можно выбрать нужные типы стрелок и настроить отображение внешних и изолированных задач.

Вкладки, выбранные задачи, добавленные вручную ключи, панели, позиции карточек и масштаб сохраняются на устройстве для текущего профиля Jira. При открытии вкладки после перезапуска задачи заново запрашиваются у Jira. В браузере после истечения сессии потребуется снова войти под тем же профилем. Команда **Рабочая область → Очистить рабочую область** начинает с одной пустой вкладки и сохраняет подключение и именованные фильтры.

Открой стрелку рядом с кнопкой обновления графа и включи **Обновлять автоматически**. Интервал можно задать в 1, 5, 10 или 15 минут. Активная вкладка обновляет задачи по последнему применённому JQL. Черновик можно редактировать во время автообновления и применить кнопкой **Загрузить граф**.

Группировка **Эпики и подзадачи** показывает эпики серыми зонами, а подзадачи располагает во вложенных зонах с названием родительской задачи. Названия берутся из Jira и для родителей за пределами выборки, когда у подключения есть доступ. В других группировках на карточке есть плашка эпика. По клику открывается отдельная вкладка с эпиком, его задачами и подзадачами. Исходный граф остаётся в своей вкладке. Если среди загруженных блокирующих связей есть цикл, над графом появляется предупреждение с количеством затронутых связей. Видимые связи в цикле выделены на полотне.

Доступны также группы по проекту, статусу, исполнителю, спринту, релизу, приоритету и уровню блокировок. Спринты различаются по цвету и значку и идут слева направо по датам начала. Если Jira вернула неполные даты, для последовательности используются номера спринтов. Внешние задачи без данных о спринте показываются в отдельной зоне. Уровни считаются по загруженным связям. Режим **Уровень открытых зависимостей** пропускает выполненные блокеры.

На панели графа можно показать предшественников или последователей, выбрать поля карточек и вывести сумму Story Points по цепочке. Поиск Jira подсказывает задачи по ключу и тексту. Выбери подсказку, чтобы найти задачу на полотне или добавить её. Добавленные ключи остаются на графе при обновлении того же JQL. Карточки и сведения о задаче показывают имя и аватар исполнителя. Если Jira не отдаёт изображение, видны инициалы.

Ширина боковых панелей меняется перетаскиванием разделителей. Кнопки панелей над графом скрывают их и возвращают. Связи прокладываются в обход карточек и стикеров. Подписи видны поверх линий и размещаются в свободном месте. Наконечник стрелки отделён от порта карточки. Меню **Экспорт** сохраняет видимую область графа в PDF или PNG с выбранным шрифтом. Файл Mermaid описывает видимые узлы, зоны, связи между видимыми узлами и стикеры.

Открой **Настройки** в верхней панели, чтобы выбрать одну из 12 светлых и тёмных тем, язык и отдельные шрифты для интерфейса и графа. В приложении 12 встроенных шрифтов с кириллицей и латиницей, доступен также системный шрифт. Шрифты загружаются из сборки приложения. Лицензии входят в неё в файле `font-licenses.txt`. Настройки применяются сразу и сохраняются на устройстве. Кнопка **Сбросить оформление** возвращает стандартную тему и шрифты. Фон карточки серый для задач к выполнению, жёлтый для задач в работе и зелёный для завершённых. Поля, введённые в Jira, отображаются в исходном языке.

### Анализ графа и планирование спринта

Открой **Анализ графа → Зависимости**. Панель показывает задачи без открытых блокеров, волны зависимостей и блокеры с числом прямых и транзитивных зависимых задач. Критический путь — цепочка с наибольшей суммой Story Points в доступной для планирования части графа. Если оценки неполные, сравнивается длина цепочек. Ключ задачи переносит к карточке, а кнопки подсветки выделяют готовые задачи или цепочку на графе.

Анализ использует загруженную выборку и известные блокирующие связи Jira. Завершённые блокеры считаются закрытыми. Открытые блокеры вне выборки и циклы отмечаются отдельно. Эпик участвует в расчёте, если у него есть открытая блокирующая связь. Волны описывают порядок блокировок, а Story Points отражают оценку объёма работы.

В **Плане спринта** укажи доступный команде лимит в Story Points. Добавь участников из исполнителей на графе или из списка проекта. Кнопка **Добавить меня** добавляет текущего пользователя Jira в сценарий. Блок **Загрузка команды** показывает участников сценария и исполнителей задач из предложенного плана. При необходимости задай индивидуальные лимиты. Планировщик предлагает задачи в порядке зависимостей и предлагает исполнителей для задач без назначения. Для одного исполнителя план размещает задачи в разных волнах. Доступны три стратегии отбора среди задач, чьи блокеры уже закрыты или включены раньше — по влиянию на зависимости, по приоритету и по размеру оценки.

План строится по задачам и подзадачам. Задачи без оценки выводятся с причиной пропуска, а оценка 0 SP учитывается. Оценки родительских задач и подзадач берутся из Jira по отдельности. Лимиты относятся к текущей выборке, поэтому учти работу команды за её пределами, когда задаёшь доступную ёмкость. Вкладка сохраняет настройки сценария локально. План и предлагаемые назначения доступны для обсуждения перед изменением спринта в Jira.

### Заметки

Нажми значок комментария на карточке, чтобы оставить заметку. Рядом с задачей появится стикер с последней заметкой и количеством записей. Клик по стикеру открывает список, где карандаш открывает редактирование заметки. В Jira заметки хранятся в комментариях с первой строкой `Jira DAG note v1`. Jira применяет права текущей учётки на чтение, создание, редактирование и удаление комментариев.

## Десктоп

Скачай установщик x64 в [GitHub Releases](https://github.com/Yekteniya2202/jira-dag/releases).

- Windows — скачай новый установщик NSIS `.exe` и запусти под тем же пользователем. Установщик находит предыдущую установку и заменяет её программные файлы, сохраняя профиль. Версия проверяется в шапке приложения после запуска.
- Linux — для Debian и Ubuntu установи новый пакет командой `sudo apt install ./jira-dag-<версия>-amd64.deb`. Для AppImage закрой приложение и замени старый файл новым.

Начиная с версии 0.10.0 в сборках Windows NSIS и Linux AppImage открой **Настройки → Обновления**, нажми **Проверить обновления**, затем **Обновить**. После загрузки появится кнопка **Перезапустить и установить**. Для пакета `.deb` приложение открывает страницу релиза. В браузере можно скачать архив, который устанавливает администратор сервера.

При включённой опции **Запомнить подключение** Jira DAG шифрует данные для входа через Electron `safeStorage` и сохраняет их в файле `jira-dag-data/connection.v1.bin` внутри каталога профиля приложения (`app.getPath('userData')`). При запуске приложение проверяет сохранённый токен в Jira. Обновление приложения сохраняет профиль текущего пользователя ОС, а кнопка **Отключить Jira** удаляет сохранённое подключение.

В Windows шифрование использует DPAPI. Для сохранения на Linux требуется системное хранилище ключей. При недоступном хранилище Jira DAG показывает сообщение и использует токен в текущей сессии.

## Браузер

У браузерной версии тот же интерфейс, а запросы Jira выполняет сервер Node.js. Каждый браузер получает отдельную сессию с собственным токеном. Токены хранятся в памяти, сессия истекает через 30 минут без запросов.

В распакованном `jira-dag-web-*.tar.gz` достаточно Node.js 24. Устанавливать npm-пакеты для запуска собранного сервера не требуется.

```powershell
$env:JIRA_ALLOWED_SITES = 'https://team.atlassian.net,https://jira.example.org/jira'
npm run start:web
```

Открой `http://127.0.0.1:8080`. Разрешённые сайты указываются точными базовыми URL через запятую. По умолчанию список пуст, доступна демонстрация. При удалённом доступе укажи внешний HTTPS-адрес в `WEB_ORIGIN` и направь запросы с него на сервер через TLS-прокси. Приложение ожидает размещения в корне этого адреса.

```bash
docker build -t jira-dag .
docker run --rm -p 127.0.0.1:8080:8080 \
  -e WEB_ORIGIN=https://dag.example.org \
  -e JIRA_ALLOWED_SITES=https://team.atlassian.net jira-dag
```

## Разработка и релизы

```bash
npm ci
npm run dev       # Electron
npm run dev:web   # браузер на 127.0.0.1:5173
npm run build
npm test
```

Для разработки с Jira в браузере задай `JIRA_ALLOWED_SITES` перед запуском `npm run dev:web`. Демо открывается сразу в обоих режимах.

Тег `vX.Y.Z`, совпадающий с версией в `package.json`, запускает сборку Windows и Linux. После тестов GitHub Actions публикует установщики, архив браузерной версии, метаданные обновления и `SHA256SUMS`. Локальные сборки запускаются через `npm run dist:win` и `npm run dist:linux` на соответствующих ОС.
