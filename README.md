# Jira DAG

Редактор направленного графа задач Jira для Windows, Linux и браузера. Карточки показывают статусы и Story Points. Стрелки представляют связи Jira, а пунктир обозначает иерархию задач.

## Использование

1. Подключи **Jira Cloud** через URL сайта, email и API-токен. Для токена с заданными разрешениями включи **scoped**. Для **Jira Data Center** укажи базовый URL, включая контекстный путь при наличии, и Personal Access Token. Имя пользователя в форме необязательно.
2. Введи JQL, например `project = APP ORDER BY key ASC`, или ключ задачи. Выбери глубину от 0 до 3, чтобы догрузить связи за пределами выборки. Узлы вне выборки отмечены пунктирной рамкой.
3. Выбери карточку, чтобы подсветить связанные ветки и увидеть открытые блокеры. При нескольких полях оценки нужное поле можно выбрать слева и обновить граф.
4. Нажми **Новая задача** или **Следующий шаг**, чтобы создать задачу в Jira. Протяни стрелку между карточками, чтобы создать связь выбранного типа. Типы, включая пользовательские, приложение читает из Jira. Для `blocks` редактор проверяет циклы в загруженной части графа.

Для чтения нужны права просмотра выбранных задач. Для записи нужны права на создание или редактирование задач и управление связями. При частичном сбое после создания задачи можно повторить привязку по её ключу. Редактор описания поддерживает простой текст. Форматированное описание Jira Cloud редактируется в Jira.

Граф зависит от JQL, глубины и прав текущей учётки. При достижении лимита или невозможности догрузить соседние задачи интерфейс показывает предупреждение. Координаты вручную перемещённых карточек действуют до следующей раскладки или загрузки.

### Выборка и раскладка

Шаблоны JQL формируют запрос по задаче, проекту, эпику, родителю подзадач, метке, спринту, релизу или сохранённому фильтру Jira. Панель слева фильтрует уже загруженные задачи по их полям и типам связей. Изолированные задачи и раздельные компоненты остаются видимыми, пока их явно не скрыли.

Группировка **Эпики и подзадачи** показывает вложенные зоны с количеством выполненных задач и суммой SP. Доступны также группы по проекту, статусу, исполнителю, спринту, релизу, приоритету и уровню блокировок. Уровни считаются по загруженным связям, в том числе когда часть задач скрыта фильтром. Режим **Уровень открытых зависимостей** пропускает выполненные блокеры. Циклические связи `blocks` выделяются на графе.

На панели графа можно показать предшественников или последователей выбранной задачи, выбрать поля карточек, вывести сумму Story Points по дальнейшей цепочке и добавить существующую задачу по ключу. Добавленные ключи остаются на графе при обновлении того же JQL. Кнопка со стрелкой на карточке открывает задачу в Jira.

Тема и язык выбираются в верхней панели и сохраняются на устройстве. Фон карточки серый для задач к выполнению, жёлтый для задач в работе и зелёный для завершённых. Поля, введённые в Jira, отображаются в исходном языке.

### Заметки

Нажми значок комментария на карточке. Заметка привязана к задаче и видна в Jira как обычный комментарий с первой строкой `Jira DAG note v1`. Редактор показывает и удаляет только комментарии с этим маркером. Jira применяет права текущей учётки на чтение, создание и удаление комментариев. Для Cloud-токена с заданными разрешениями нужны права API для комментариев и избранных фильтров, если ты используешь эти функции.

## Десктоп

Скачай установщик x64 в [GitHub Releases](https://github.com/Yekteniya2202/jira-dag/releases).

- Windows — установщик NSIS `.exe`.
- Linux — `.deb` для Debian и Ubuntu или переносимый AppImage.

Токен хранится в памяти процесса Electron. После выхода из приложения понадобится подключиться заново.

## Браузер

У браузерной версии тот же интерфейс, а запросы Jira выполняет сервер Node.js. Каждый браузер получает отдельную сессию с собственным токеном. Токены хранятся в памяти, сессия истекает через 30 минут без запросов.

В распакованном `jira-dag-web-*.tar.gz` достаточно Node.js 24. Устанавливать npm-пакеты для запуска собранного сервера не требуется.

```powershell
$env:JIRA_ALLOWED_SITES = 'https://team.atlassian.net,https://jira.example.org/jira'
npm run start:web
```

Открой `http://127.0.0.1:8080`. Разрешённые сайты указываются точными базовыми URL через запятую. По умолчанию список пуст, доступна демонстрация. При удалённом доступе укажи внешний HTTPS-адрес в `WEB_ORIGIN` и направь запросы с него на сервер через TLS-прокси. Приложение ожидает размещения в корне этого адреса.

```bash
docker build -t jira-dag .
docker run --rm -p 127.0.0.1:8080:8080 \
  -e WEB_ORIGIN=https://dag.example.org \
  -e JIRA_ALLOWED_SITES=https://team.atlassian.net jira-dag
```

## Разработка и релизы

```bash
npm ci
npm run dev       # Electron
npm run dev:web   # браузер на 127.0.0.1:5173
npm run build
npm test
```

Для разработки с Jira в браузере задай `JIRA_ALLOWED_SITES` перед запуском `npm run dev:web`. Демо открывается сразу в обоих режимах.

Тег `vX.Y.Z`, совпадающий с версией в `package.json`, запускает сборку Windows и Linux. После тестов GitHub Actions публикует установщики, архив браузерной версии и `SHA256SUMS`. Локальные сборки запускаются через `npm run dist:win` и `npm run dist:linux` на соответствующих ОС.
