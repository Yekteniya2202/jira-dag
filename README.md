# Jira DAG

Редактор направленного графа задач Jira для Windows, Linux и браузера. Карточки показывают статусы и Story Points. Стрелки представляют связи Jira, а пунктир обозначает иерархию задач.

## Использование

1. Подключи **Jira Cloud** через URL сайта, email и API-токен. Для токена с заданными разрешениями включи **scoped**. Для **Jira Data Center** укажи базовый URL, включая контекстный путь при наличии, и Personal Access Token. Имя пользователя в форме необязательно.
2. Введи JQL, например `project = APP ORDER BY key ASC`, или ключ задачи. Выбери глубину от 0 до 3, чтобы догрузить связи за пределами выборки. Узлы вне выборки отмечены пунктирной рамкой.
3. Выбери карточку, чтобы подсветить связанные ветки и увидеть открытые блокеры. При нескольких полях оценки нужное поле можно выбрать слева и обновить граф.
4. Нажми **Новая задача** или **Следующий шаг**, чтобы создать задачу в Jira. Протяни стрелку между карточками, чтобы создать связь выбранного типа. Типы, включая пользовательские, приложение читает из Jira. Для `blocks` редактор проверяет циклы в загруженной части графа.

Для чтения нужны права просмотра выбранных задач. Для записи нужны права на создание или редактирование задач и управление связями. Автор новой задачи берётся из текущего профиля Jira. Кнопка **+** на карточке открывает создание следующей задачи с выбором типа связи. При частичном сбое после создания можно повторить привязку по её ключу. Кнопка **Открыть описание** показывает Markdown в модальном окне. Форматированное описание Jira Cloud редактируется в Jira.

Граф зависит от JQL, глубины и прав текущей учётки. При достижении лимита или невозможности догрузить соседние задачи интерфейс показывает предупреждение. Координаты вручную перемещённых карточек действуют до следующей раскладки или загрузки.

### Выборка и раскладка

Выбери доступный проект Jira из списка. Проект, шаблоны и фильтры по полям задач добавляют условия в один редактируемый JQL. Нажми **Загрузить граф**, чтобы отправить запрос в Jira. Если черновик отличается от применённого запроса, под редактором виден JQL загруженного графа. Числа рядом со значениями относятся к задачам текущей загруженной выборки. Глубина **Только выборка** показывает задачи, найденные по JQL. Для добавления соседних задач выбери глубину от одного до трёх переходов.

Открой новую вкладку кнопкой **+**. У каждой вкладки свой JQL, загруженный граф, фильтры и настройки отображения. Вкладки доступны в текущем сеансе приложения. В свёрнутой панели **Подсветка на графе** можно выделить задачи по тексту и полям. В меню **Видимость связей** можно выбрать нужные типы стрелок и настроить отображение внешних и изолированных задач.

Группировка **Эпики и подзадачи** показывает эпики серыми зонами, а подзадачи располагает во вложенных зонах. Заголовок зоны открывает сведения об эпике и его связи. Карточка эпика и её стрелки доступны в других группировках. Если среди загруженных блокирующих связей есть цикл, над графом появляется предупреждение с количеством затронутых связей. Видимые связи в цикле выделены на полотне.

Доступны также группы по проекту, статусу, исполнителю, спринту, релизу, приоритету и уровню блокировок. Спринты различаются по цвету и значку. Внешние задачи без данных о спринте показываются в отдельной зоне. Уровни считаются по загруженным связям. Режим **Уровень открытых зависимостей** пропускает выполненные блокеры.

На панели графа можно показать предшественников или последователей, выбрать поля карточек и вывести сумму Story Points по цепочке. Поиск Jira подсказывает задачи по ключу и тексту. Выбери подсказку, чтобы найти задачу на полотне или добавить её. Добавленные ключи остаются на графе при обновлении того же JQL. На карточке видно имя исполнителя, а в сведениях о выбранной задаче появляется аватар Jira, если его удалось загрузить.

Ширина боковых панелей меняется перетаскиванием разделителей. Кнопки панелей над графом скрывают их и возвращают. Меню **Экспорт** сохраняет видимую область графа в PDF или PNG. Файл Mermaid описывает видимые узлы, зоны, связи между видимыми узлами и стикеры.

Тема и язык выбираются в верхней панели и сохраняются на устройстве. Фон карточки серый для задач к выполнению, жёлтый для задач в работе и зелёный для завершённых. Поля, введённые в Jira, отображаются в исходном языке.

### Заметки

Нажми значок комментария на карточке, чтобы оставить заметку. Рядом с задачей появится стикер с последней заметкой и количеством записей. Клик по стикеру открывает список. В Jira заметки хранятся в комментариях с первой строкой `Jira DAG note v1`. Jira применяет права текущей учётки на чтение, создание и удаление комментариев.

## Десктоп

Скачай установщик x64 в [GitHub Releases](https://github.com/Yekteniya2202/jira-dag/releases).

- Windows — скачай новый установщик NSIS `.exe` и запусти под тем же пользователем. Установщик находит предыдущую установку и заменяет её программные файлы, сохраняя профиль. Версия проверяется в шапке приложения после запуска.
- Linux — для Debian и Ubuntu установи новый пакет командой `sudo apt install ./jira-dag-<версия>-amd64.deb`. Для AppImage закрой приложение и замени старый файл новым.

Новые версии нужно скачивать и устанавливать вручную из GitHub Releases.

При включённой опции **Запомнить подключение** Jira DAG шифрует данные для входа через Electron `safeStorage` и сохраняет их в файле `jira-dag-data/connection.v1.bin` внутри каталога профиля приложения (`app.getPath('userData')`). При запуске приложение проверяет сохранённый токен в Jira. Обновление приложения сохраняет профиль текущего пользователя ОС, а кнопка **Отключить Jira** удаляет сохранённое подключение.

В Windows шифрование использует DPAPI. Для сохранения на Linux требуется системное хранилище ключей. При недоступном хранилище Jira DAG показывает сообщение и использует токен в текущей сессии.

## Браузер

У браузерной версии тот же интерфейс, а запросы Jira выполняет сервер Node.js. Каждый браузер получает отдельную сессию с собственным токеном. Токены хранятся в памяти, сессия истекает через 30 минут без запросов.

В распакованном `jira-dag-web-*.tar.gz` достаточно Node.js 24. Устанавливать npm-пакеты для запуска собранного сервера не требуется.

```powershell
$env:JIRA_ALLOWED_SITES = 'https://team.atlassian.net,https://jira.example.org/jira'
npm run start:web
```

Открой `http://127.0.0.1:8080`. Разрешённые сайты указываются точными базовыми URL через запятую. По умолчанию список пуст, доступна демонстрация. При удалённом доступе укажи внешний HTTPS-адрес в `WEB_ORIGIN` и направь запросы с него на сервер через TLS-прокси. Приложение ожидает размещения в корне этого адреса.

```bash
docker build -t jira-dag .
docker run --rm -p 127.0.0.1:8080:8080 \
  -e WEB_ORIGIN=https://dag.example.org \
  -e JIRA_ALLOWED_SITES=https://team.atlassian.net jira-dag
```

## Разработка и релизы

```bash
npm ci
npm run dev       # Electron
npm run dev:web   # браузер на 127.0.0.1:5173
npm run build
npm test
```

Для разработки с Jira в браузере задай `JIRA_ALLOWED_SITES` перед запуском `npm run dev:web`. Демо открывается сразу в обоих режимах.

Тег `vX.Y.Z`, совпадающий с версией в `package.json`, запускает сборку Windows и Linux. После тестов GitHub Actions публикует установщики, архив браузерной версии и `SHA256SUMS`. Локальные сборки запускаются через `npm run dist:win` и `npm run dist:linux` на соответствующих ОС.
